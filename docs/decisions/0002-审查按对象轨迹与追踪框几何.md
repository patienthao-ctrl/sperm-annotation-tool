# 0002 审查按对象轨迹进行，补齐追踪框几何的漏洞

- 日期：2026-11-01
- 状态：采用

## 背景

用户审查反馈三类问题最常见：标注框被杂质干扰变大；精子出画后仍有一两帧残留框；框整体偏大需要收缩。这些问题帧都没有出现在审查清单（含随机抽检）里，审查员最终逐帧看完全片、修改后把抽检全部标为“无误”才通过——因为标“已修正”≥2 次会触发加抽（`ESCALATE_AFTER_FIXED_SAMPLES`）。另外，审查员修改某帧后，前后帧往往存在同样的问题却没有被修改。

调查结论（代码事实）：

1. **清单没有框几何规则。** `annotation_review.py` 的疑点只有漏标、跟错、偏离头部、静止、轨迹中途结束、计数突变；`area_ok` 只过滤漏标候选，不检查已有框。`track_ended_items` 对贴边结束的轨迹 `continue`，出画残留恰好被跳过。随机抽检最多 20 帧（2%），抽中连续 1–3 帧问题的概率很低。
2. **错误按对象成段出现，审查按帧发现、按帧修改。** 审查模式隐藏追踪控件，除全视频删除外没有区间操作，也不提示相邻帧。
3. **“SAM3 负责身份、检测器负责几何”已经实现**（`joint_tracking.py`，`joint-head-v1`，仅首尾双向追踪 `combineResults=true` 时运行）。每帧候选为正向 F、反向 R、检测 D、近邻中值 C；单项代价中检测偏差权重 2，F/R 各 0.6，所以一旦 D 被采用，框几何基本由检测器决定。漏洞在 D 用不上的时候：
   - D 需置信度 ≥0.7 且局部唯一，竞争候选不硬配。杂质贴着头部时恰好容易出现第二个候选或低置信度，于是该帧只剩 SAM3 的 F/R/C；路径代价只约束“与上一帧相比的尺度变化”，没有“不得远大于该对象常态尺寸”，F/R 都被撑大时无更小选项。
   - “检测器缺失不删对象”；`track_lifecycle.protect_boundary_exits` 需同时满足向边缘运动、裁切、主体丢失和借用邻居才终止身份，普通出画的残留掩码保留下来。
   - D 主导几何，框的松紧继承检测器训练数据的习惯。现检测器 `yolo26s-svia-head-v1` 只用公开 SVIA 训练，从未用医院数据微调（已与用户确认）。整体偏大是否来源于此**尚未核实**。
   - 单向“AI Tracking”续追不经过融合，框完全来自 SAM3；首尾帧不跑检测（人工框）。

## 决定

审查单位从“帧”改为“对象的一段轨迹”；追踪在现有融合上补漏洞，不另起一套；模型迭代以医院审查数据为基础、以固定测试集评估。分五部分：

### 一、改帧联动（审查）

审查员修改对象 X 在第 N 帧的框后，系统比较 X 在 N 前后若干帧的框，差异明显（暂定尺寸差 >30% 或中心偏移 > 半个头宽）时在画面提示，并提供区间操作：

- 调整/缩小框 →“把此尺寸应用到第 a–b 帧”：保留各帧中心，只改宽高；遇人工框停止；先预览后确认。
- 删除残留框 →“删除此对象第 a–b 帧 / 从本帧到轨迹结束”。
- 补框 →“向前/向后补框”：复用点选头部检测在邻近位置逐帧寻找，不是同一个头即停；补上的框是审查员确认操作产生的人工框（`origin=linked_fill`，可撤销），不在审查模式重开整段追踪。

被修改的帧段自动生成一项“联动检查”。区间操作仍走现有保存协议（版本校验、幂等键、撤销），产生的修改照常进入 `changes_json`。

### 二、按对象检查视图（审查）

选中对象后，把它每帧框附近区域裁成缩略图排成条带/网格，上方画框面积曲线；点缩略图跳到该帧，可框选多张统一删除或统一尺寸。目标是替代“逐帧看完全片”。布局须归入 `WorkbenchShell` 现有区域，不新增常驻整行。

### 三、新增几何疑点与抽检规则调整（审查）

- “框大小异常”：同一对象框面积与其 ±5 帧中位数之比 ≥1.6 或 ≤0.6，连续帧合并为一项；对象全程中位面积 ≥ 视频头框中位面积 1.8 倍时提示“框整体偏大”。
- “出画尾帧”：轨迹贴边结束且最后几帧无检测框支持时，列出最后 2–3 帧，供一键删除或收缩。不自动删除。
- 加抽不再惩罚如实标记：改为在已修正帧附近、同一对象轨迹上定点复查，不再随机加抽。
- 阈值为首版估计，实现时用测试视频校准清单长度；纳入 `EVIDENCE_POLICY` 摘要，旧清单按现有版本化规则重建。

### 四、追踪融合补漏洞（追踪，B 的改进 + C）

- 在 `options` 中增加尺寸约束候选 S：中心取 SAM3 框，宽高取该对象在检测器支持帧上的中值；仍由 `temporal_path` 选择，不强制替换。只在 D 缺席或未被采用的帧生效；人工框和删除墓碑优先不变。
- 出画残留不在追踪中自动删除（保持“检测器缺失不删对象”），交给第三部分的“出画尾帧”审查项。
- 改动改变后续追踪输出，`POLICY` 升版本；已有追踪结果、人工框、删除记录和已通过的审查不改写。

### 五、检测模型迭代

- 先建固定测试集：从审查通过的医院视频中挑选一批（覆盖不同浓度与杂质），永不进入训练集，用单独的视频名单固定，不依赖导出时按 SHA 的自动分组。
- 训练–评估一条命令：合并已通过导出包 → 训练 → 在固定测试集上与当前模型比较 → 生成版本记录（使用的视频/快照、参数、指标）。可一周 2–3 次训练评估；发布到医院按需要、明显变好时进行，频率低于训练。
- 指标：医院测试集上的召回率、精确率与框紧度（与公开数据分开统计）；以及审查工作量（清单项数、每百帧修改次数）。
- 训练包需区分“审查员修改过的框”和“原样通过的框”；`not_target` 与删除的残留框作为难负样本来源。
- 权重分发方式（继续替换 Git 中的 `head-detector.pt`，或像 SAM3 一样经 Release 分发）待定，须遵守 AGENTS 中“Git 只允许这一个权重”的约定和离线升级契约。
- 用途确认为非商业，现有 AGPL-3.0 与 SVIA 非商业研究条款可继续使用，保留模型说明。

## 实施顺序

1. 改帧联动（第一部分）——改动小，直接解决“改了一帧、相邻帧没改”。
2. 几何疑点与抽检调整（第三部分）。
3. 追踪尺寸约束候选 S（第四部分），用测试视频比较改前改后。
4. 按对象检查视图（第二部分）——工作量最大，先做简易版在一个视频上试用。
5. 固定测试集与首次医院数据微调（第五部分），可与 1–4 并行准备数据。

每一步单独提交，并按 AGENTS 的测试分层验证；用户可见流程变化同步 `frontend/src/help/user-guide.md`。

## 放弃的方案及原因

- **只靠提高随机抽检比例**：连续 1–3 帧的问题仍难被抽中，审查量却线性增加。
- **改用纯检测逐帧再关联（tracking-by-detection）替代 SAM3**：框更紧，但漏检会断轨、交叉时易串号；现有融合已经让检测器主导几何，补漏洞的成本更低。
- **检测器缺失或贴边即自动删框**：违背“检测器缺少一次候选不删对象”；单帧漏检常见，会误删真实目标。改为审查项由人确认。
- **只做后处理平滑（纯 C）**：能压住明显异常，但对整体偏大无效，也不能利用检测器信息。
- **先统计现有审查记录再决定**：用户决定不统计真实业务数据；改用测试视频对比与试用反馈校准。

## 待确认

- 问题通常连续几帧？决定联动检查范围（暂定前后 5 帧）。
- 整体偏大是否来自检测器：在同一头部比较“点选头部”生成的框与手画框即可核实。
- 审查员的使用习惯与每视频可接受审查时长（目前未知）。
- 检测器权重的分发方式；固定测试集的视频名单与负责人。
